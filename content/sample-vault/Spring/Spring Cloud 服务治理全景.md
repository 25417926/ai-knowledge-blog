# Spring Cloud 服务治理全景

微服务不是"把单体拆开"这么简单。拆开之后，原本靠方法调用解决的问题，全部变成了分布式问题。

## 五类治理能力

1. **注册与发现**：服务实例的地址从哪来。核心是 [[Nacos 服务注册与配置中心]]。
2. **配置管理**：多环境、动态刷新、灰度。
3. **网关**：统一入口，做路由、鉴权、限流。
4. **容错**：熔断、降级、隔离。
5. **可观测**：链路追踪、指标、日志聚合。

## 一组容易混的概念

- **熔断 vs 降级**：熔断是"不再调用"，降级是"调用替代逻辑"。熔断触发后通常走降级。
- **限流 vs 隔离**：限流控制进入速率，隔离控制资源池边界。两者常配合使用。
- **强一致 vs 最终一致**：跨服务事务能不用就不用，优先用本地消息表做最终一致。

## 学习路径建议

不要按组件清单逐个学，而是**按一次请求的完整路径**学：请求 → 网关 → 服务发现 → 负载均衡 → 调用 → 熔断 → 链路追踪。走通一条链路，组件之间的关系自然就懂了。
