# JVM 内存结构与垃圾回收

## 运行时的几块地

- **堆**：对象实例，所有线程共享，GC 的主战场。
- **虚拟机栈**：线程私有，每个方法调用一个栈帧，存局部变量表与操作数栈。
- **元空间**：类元数据，JDK 8 起从永久代移到本地内存。
- **程序计数器**：唯一不会 OOM 的区域。

## 分代回收为什么成立

弱分代假说：绝大多数对象朝生夕死。于是新生代用复制算法，只付出少量存活对象的拷贝成本；老年代用标记整理，避免碎片。

## 三类垃圾收集器

- **Serial**：单线程，适合客户端小堆。
- **G1**：把堆切成 Region，可预测停顿，是目前服务端默认。
- **ZGC**：染色指针 + 读屏障，停顿在毫秒级，适合大堆低延迟场景。

## 排查内存问题的顺序

先看 GC 日志的回收频率与耗时，再看堆转储确认对象是谁持有的。**不要一上来就调参数**——90% 的内存问题根因在代码持有引用，而不在堆大小。
