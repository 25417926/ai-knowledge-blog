# RAG 检索增强生成基础

RAG 的本质是：**用检索结果给模型的回答划一个可验证的边界**。它解决的不是"模型不够聪明"，而是"模型不知道你的私有内容"。

## 五个环节

1. **切分**：按语义边界切，不要按固定字数硬切。按标题层级切通常优于按字符数切。
2. **向量化**：把文本块映射成向量。切分质量差，再好的 embedding 也救不回来。
3. **检索**：算相似度取 Top-K。原理见 [[向量检索与余弦相似度]]。
4. **重排**：对 Top-K 用更贵的模型精排，把真正相关的提到前面。
5. **生成**：把检索到的片段塞进上下文，并要求模型**只依据给定片段回答**。

## 三个最常见的坑

**坑一：切分太碎。** 一个完整的论证被切成三段，检索到其中一段，模型只能看到半句话。宁可块大一点，配合重叠。

**坑二：只要向量检索。** 向量擅长语义近似，但对**精确匹配**（版本号、函数名、错误码）反而弱。生产环境通常是向量 + 关键词双路召回再融合。

**坑三：没有引用。** 不标注来源的 RAG 等于没有 RAG——用户无法验证，你也无法定位是检索错了还是生成错了。引用必须能点回到原文段落。

## 与 Agent 的关系

RAG 是 Agent 记忆层的检索手段之一，但它不等于记忆：RAG 检索的是**外部知识**，记忆存的是**与用户的交互历史**。两者结构相似、用途不同。
