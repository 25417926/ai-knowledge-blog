# Agent 工程师能力模型

从后端转 Agent 不是"学个框架"的事。真正的门槛在**把不确定的模型能力包成可靠的系统**。

## 四层能力

1. **模型层**：知道什么任务该用哪个模型，理解上下文窗口、温度、结构化输出这些旋钮的实际影响。切入点是 [[提示工程的结构化写法]]。
2. **编排层**：任务怎么拆、工具怎么调、失败了怎么重试。这一层决定 Agent 的能力上限。
3. **记忆层**：短期对话窗口怎么管、长期事实怎么沉淀、什么时候该忘。这是最容易做浅的一层。参见 [[RAG 检索增强生成基础]]。
4. **工程层**：可观测、可评测、成本可控。没有这一层，Agent 永远停在 demo。

## 一个判断标准

能区分"这次回答不好"和"系统设计有问题"，是初级和中级的分界线。前者调提示词，后者改架构。

## 与后端能力的复用

后端经验在 Agent 领域**不是清零**，而是换了个对象：

- 线程池/队列 → 并发调用与限流
- 服务治理 → 模型与工具的降级、熔断
- 缓存 → 语义缓存与检索结果复用

所以 [[Java 并发编程知识地图]] 和 [[Spring Cloud 服务治理全景]] 里的判断力，换个场景依然成立。
