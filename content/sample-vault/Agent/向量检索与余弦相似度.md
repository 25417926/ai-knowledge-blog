# 向量检索与余弦相似度

## 余弦相似度

两个向量的夹角余弦：`cos(a,b) = (a·b) / (|a| |b|)`。

取值在 -1 到 1 之间，越接近 1 越相似。关键性质是**只看方向不看长度**——文本向量里，长度常常反映篇幅而不是语义，所以方向比距离更能代表"说的是同一件事"。

## 为什么常归一化

如果把向量预先归一化成单位长度（`|a| = 1`），余弦相似度就退化成**点积**。这样检索时只需一次矩阵乘法，省掉每次算模长的开销。多数向量库内部就是这么做的。

## 小规模场景不需要向量数据库

一个反直觉的结论：**几万条以内的向量，内存里暴力算余弦比上向量数据库更快。**

- 10,000 条 × 768 维浮点 = 约 30MB，全量算一次点积在现代 CPU 上是毫秒级。
- 引入 pgvector / Milvus 的收益要到百万级向量才显现，而运维成本从第一天就要付。

所以本项目的做法是：向量以 BLOB 存在 SQLite，检索时读进内存算余弦。零额外依赖，换台机器照样跑。

## 什么时候必须上专用索引

- 向量量级进入百万级以上
- 需要 HNSW / IVF 这类近似最近邻来换速度
- 需要多副本与在线更新

在此之前，把所有复杂度挡在门外，是更划算的决定。
